- **최종 목표:** L1(UTP 케이블 제작)부터 L7(HTTP)까지 전 계층을 구성하고, 상이한 VLAN 간 라우팅 및 웹 서비스 통신 검증

## 1. 네트워크 토폴로지 및 인터페이스 구성

### 🔷 L3 스위치 (MLS3)

- `Fa0/24`: Trunk 포트 (SW3 `Fa0/24` 연동)
- `Fa0/1`: Routed Port (IP: `172.16.0.30/16`)
- `VLAN 10 SVI`: `192.168.50.1 255.255.255.0` (PC17의 기본 게이트웨이)
- `VLAN 20 SVI`: `192.168.60.1 255.255.255.0` (PC18의 기본 게이트웨이)

### 🔷 L2 스위치 (SW3)

- `Fa0/24`: Trunk 포트 (MLS3 `Fa0/24` 연동)
- `Fa0/1 ~ Fa0/6`: VLAN 10 Access 포트
- `Fa0/7 ~ Fa0/12`: VLAN 20 Access 포트

## 2. 작업 절차 및 계층별 구현

### Step 1. L1 계층 - UTP 다이렉트 케이블 제작

- **규격:** T568B (주흰-주-초흰-파-파흰-초-갈흰-갈)
- **작업 핵심:**
    1. 피복 입구 바로 앞까지 심선 꼬임을 완전히 풀어주어야 8가닥이 부채꼴로 벌어지지 않고 반듯하게 밀착됨.
    2. 일자 정렬 후 심선 길이를 약 **1.2~1.3cm**로 수평 직각 커팅.
    3. 압착 시 커넥터 내부 사각 턱이 **겉피복을 3~5mm 이상 물고 들어간 상태**에서 찝어야 물리적 인장력이 확보됨.

### Step 2. L2/L3 계층 - VLAN 분할 및 Inter-VLAN 라우팅

- SW3에서 `Fa0/1`은 VLAN 10, `Fa0/7`은 VLAN 20으로 포트 격리.
- 스위치 간 `Fa0/24` 포트를 802.1Q 트렁크로 개방하여 단일 케이블로 멀티 VLAN 트래픽 전송.
- MLS3의 SVI(Switch Virtual Interface)를 통해 `192.168.50.0/24` 대역과 `192.168.60.0/24` 대역 간 라우팅 수행.

### Step 3. L4/L7 계층 - 파이썬 웹 서버 및 윈도우 방화벽

- **Python HTTP 서버 실행:**
    - 경로: `C:\Users\sec18\Desktop\엄지호\실물장비실습\web\index.html`
    - 명령어: `python -m http.server 8000` 실행
- **Windows Defender 방화벽 예외 설정 (PC18):**
    - TCP 8000번 포트 인바운드 허용
    - IPv4 ICMP(Ping) 에코 요청 허용

## 3. 핵심 기술 인사이트 & 트러블슈팅

### 💡 트러블슈팅: 웹 통신 불가 원인 규명

- **증상:** PC17에서 `http://192.168.60.2:8000` 접속 실패.
- **원인 추적:**
    - 방화벽 설정 점검 중 물리 계층 확인 ➔ **L2(SW3)와 L3(MLS3) 간 트렁크 연결 케이블 미체결 확인.**
    - 케이블 체결 즉시 정상 통신 성공.
- **교훈 (Bottom-Up 접근법):**
    - 네트워크 장애 발생 시 상위 설정(라우팅, 방화벽) 이전에 **L1(케이블 체결 및 링크 LED 점등) ➔ L2(VLAN/Trunk) ➔ L3(IP/Routing)** 순서로 상향 점검하는 것이 트러블슈팅의 정석.

### 💡 상태 저장 방화벽(Stateful Inspection)의 이해

- **서버(PC18):** 외부에서 들어오는 연결(SYN)을 최초 수신하므로 **인바운드 8000번 포트 허용 규칙이 필수**.
- **클라이언트(PC17):** 내부에서 외부로 나가는 연결(Outbound)을 능동적으로 시작하므로, 방화벽이 상태 테이블(State Table)에 세션을 기록해 두었다가 돌아오는 웹 응답 패킷(SYN-ACK/ACK)을 자동 허용함. **따라서 클라이언트 PC의 방화벽은 끄거나 예외를 열 필요가 없음.**
